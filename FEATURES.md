# rpi core features

Inventory of shipped product capabilities in the current tree. Sources: `README.md`, `docs/src/SUMMARY.md`, `crates/pi-cli/src/args.rs`, `crates/pi-cli/src/interactive_commands.rs` (`BUILTIN_COMMANDS`), `crates/pi-coding/src/tools.rs` (`TOOL_NAMES`), `crates/pi-cli/src/modes/listen.rs`, and the pages under `docs/src/`.

The executable is `rpi`. Runtime dir: `PI_CODING_AGENT_DIR` > `RPI_HOME` > `~/.rpi` (`%USERPROFILE%\.rpi` on Windows). Project dir is `.rpi/`.

When a change adds, removes, or changes a user-visible capability, update this file in that same change (`AGENTS.md` Documentation Standards). Inventory E2E: `bash E2E.d/features.sh` (map: `bash E2E.d/features.sh list`).

## Surfaces

| Surface | How it is selected |
|---|---|
| Print | `-p` / `--print`, or non-terminal stdin/stdout **and** a non-empty prompt (`lib.rs` `main_run`). Empty prompt stays interactive. |
| JSON event stream | `--mode json` |
| JSONL RPC | `--mode rpc` or `rpi rpc` |
| Line REPL | interactive, but not a full terminal pair |
| TUI | both stdin and stdout are terminals (`crossterm` + `ratatui`, inline / no alt-screen) |
| Web listener | `--listen` HTTPS/WebSocket; never starts TUI/REPL; positional prompts are rejected |
| ACP | `rpi agent stdio` / `rpi agent serve` (Agent Client Protocol) |

TUI and Web share the same session/RPC core. Platform-only gaps are called out below.

`--listen` HTTP paths (`listen.rs`):

| Path | Role |
|---|---|
| `/web` | operator SPA; Teams liveness probe (`GET` 200 `text/html` with rpi markers, `team.rs`); the header module menu (`#feature-menu-btn`, `panel-toggle`) opens the body-portal `#feature-menu`; its `#sidebar-menu-item` Sessions entry toggles the Sessions sidebar; a close (1006/1008), heartbeat timeout, send failure, or bootstrap failure covers the whole page (`#reconnect-overlay`, spinner + `连接断开，正在重连…`) until reconnect bootstrap finishes; application ping every 5s; web document serving negotiates gzip (single-slot content-keyed cache, weak ETag, `Vary: accept-encoding`), answers `If-None-Match` with a zero-body 304 on match (list/`*`/weak comparison), and answers HEAD with GET headers and no body; a ping dies only after 10s with no inbound frame at all (any post-ping frame, including a large transcript, counts as alive); server idle kick 30s; reconnect backoff 250ms–5s and heartbeat/stale close resets that delay immediately; wake of an OPEN socket always pings (application-message age is not a tear-down); hidden-tab heartbeat timers do not retire the socket; a background-aged outstanding ping and silence timer are dropped and a fresh probe is sent; a truly dead socket still dies on the 10s missed-pong path after the page is visible; refill/session_list bootstrap failures retry twice at 1.5s then fail closed so the overlay stays; header chip remains a compact pulsing warn mark on connecting/reconnecting (`chat-slow-pulse`; `aria-label` is `Connecting…` while connecting without a stream stall, otherwise `Reconnecting…`); raw error only for token_required |
| `/chat` | LAN ChatApp (projects, runner invite, mapped sessions); selected-runner connecting/reconnecting/offline uses the same `#reconnect-overlay` over the workspace shell; transports stay mounted across `pagehide` (an app switch, not an unmount), and a visible/focus/`pageshow` wake sends one session-stamped `get_state` liveness probe on a connected OPEN runner — a blackholed probe's 15s timeout fails it into reconnect. The project header's selected-conversation runner status prints `Connecting…` while connecting and `Reconnecting…` while reconnecting |
| `/ws` | WebSocket control plane |
| `/rpc` | JSON-RPC POST |
| `/status` | listener status |
| `/upload/video`, `/upload/pdf`, `/upload/tmux-file` | authenticated composer attachment extract; tmux-file writes a temp path and pastes it into a tmux session |
| `/collab/ws/<room>` | collaboration guest room (`collab_room_id`) |

Pairing: banner prints `{origin}/web` or `{origin}/web#{token}` (`lib.rs`). Tokenless loopback is optional; non-loopback requires `--listen-token-file` unless `--listen-allow-insecure-remote`. Wildcard binds need `--listen-advertised-origin`. Missing token on a required listener opens `TokenPairingCard` (`token_required`), not an unauthenticated reconnect loop. A stored token whose `/ws` handshake never opens still auto-reconnects unless an authenticated `POST /rpc` probe confirms HTTP 401.

Composer Command picker lists builtins, skills, and trusted extension commands; submitting `/name` dispatches RPC `run` (TUI `/name` and `/run`). Prompt templates stay out of the picker. Typing a `/` token in the composer opens an inline candidate list from the same catalog: Enter selects the highlighted candidate (the first by default) and never auto-sends, ArrowUp/ArrowDown move the highlight, Esc closes, a token with no candidates keeps the normal submit, and IME composition or the paste Enter guard never trigger a select.

**Composer edit keys:** Ctrl+U clears the whole draft text (attachments preserved); Ctrl+A / Ctrl+E move to the current physical line's start/end; Ctrl+W deletes the selection or the previous word (OMP word classes — whitespace, CJK run, latin word with joiners, punctuation/symbol run, one other grapheme; at a line start it deletes the joining newline). Ctrl-only: meta/alt/shift pass through and IME composition is never intercepted. Ctrl+W delivery depends on the browser (e.g. Chrome reserves Ctrl+W) — it works only as delivered by the browser, not by promise.

**Composer attachments** (`attachments.ts`, four kinds; prompt frame cap `MAX_RPC_MESSAGE_BYTES` 4 MiB):

| Kind | Wire |
|---|---|
| image | `ContentBlock::Image` on `prompt.images` |
| video | `POST /upload/video` → ffmpeg JPEG frames + instruction text (never raw video on the prompt frame) |
| pdf | `POST /upload/pdf` → pdftotext + instruction text |
| code | UTF-8 text fenced into `prompt.message` |

Other binaries and invalid UTF-8 are rejected at intake with a visible reason. `/web` and `/chat` image and code chips include Send to terminal (`POST /upload/tmux-file`): allowlist png/jpeg/gif/webp/pdf and UTF-8 text/code, 8 MiB cap, temp file deleted after 5 minutes; the path is pasted into the overlay runner's tmux session and toasted. The upload posts to the overlay destination's runner authority (typed `runnerId` + session), not the current page host. The `/chat` tmux overlay soft-key bar has an Upload control next to Ctrl that posts the same `/upload/tmux-file` endpoint to the overlay session and toasts the returned path.

**Composer interrupt:** `/web` and `/chat` ■ Stop (pointerdown) flip the footer to stopped (Send) immediately, before abort RPC resolves, then send RPC `abort` for the displayed session, including while a tool such as bash is running. Live `isStreaming=true` events and `get_state` cannot re-arm Stop until abort settles or a new `turn_started`. After abort, `get_state` confirms idle. The tap is not gated on a client streaming flag. Abort RPC failures toast. Toasts stack above `--app-footer-height` so they never cover Stop. TUI Esc/Ctrl-C uses the same `Application::abort` (bash then agent; in-flight brush bash is killed, not waited out).

**Composer Enter:** `/web` and `/chat` composers send on Enter (Shift+Enter stays a newline). `#prompt-input` and `/chat` composer textarea are 16px at every width so iOS Safari does not auto-zoom a 13px field and steal taps from the composer, Stop, and the steering tray. Android GBoard may leave `isComposing: true` on the send key after `compositionend`; that Enter still submits. `beforeinput` `insertParagraph`/`insertLineBreak` submits when keydown did not. Submit, hold-to-talk, and Live refuse to start unless the socket is authoritative-ready (`connState === 'on'`, no bootstrap in flight, WebSocket OPEN); Enter before that dispatches nothing and keeps the typed draft, and a cold bind seeds that live draft into the new runtime's view slot so the first bind does not wipe it. Enter always requests `prompt`; `planComposerSubmitKind` converts to `steer` only from the session streaming ref. `/web` submit claims a `composerSendingRef` that spans `sendCommand` ACK for dispatched sends; validation and local panel actions that do not send release immediately.

**Steering:** `/queue`; modes `all` / `one-at-a-time` (`QueueMode` kebab-case). Web composer tray: one 36–44px row per queued message (label + ellipsized preview + send now / cancel), on one composer status row (activity state left, queue right) on `/web` and `/chat` including 390px (footer overflow stays visible so the tray is not clipped). While a turn is processing, `/web` and `/chat` composer submit send `steer` (not `prompt`) from `streamingBySessionId` / turn-level live streaming (`turn_terminal` clears it; inner `message_end` does not); a typed `session_processing` prompt rejection resends the same content as `steer` once. Optimistic tray rows survive empty `get_state` until a live `queue_update`. Live sequence gaps resubscribe once and probe `get_state` (auxiliary, coalesced); an idle snapshot then requests one settled `get_messages` refill. `busy_capacity` catch-up and reconnect-refill failures stay silent. Queue shrink is not treated as consumption. Send now (`queue_send_now`) aborts the in-flight turn, waits until idle, then prompts the combined steering as a new turn (it does not re-enqueue via `steer`). The tray clears only on authoritative `queue_update`. Cancel of an already-consumed row is a no-op success, not a stuck button. A steer that exceeds the 4 MiB RPC frame is refused before the composer clears, with the size-limit toast; other steer RPC failures toast the server reason and drop that optimistic row. A live sequence gap or `get_state.isStreaming === false` while a streaming assistant is still painted refills `get_messages` so a missed `turn_terminal` cannot freeze the transcript mid-reply. While a turn is streaming, 5s without a sequenced event `get_state`s (then that same refill) and paints the `/web` footer activity strip plus header chip as pulsing Reconnecting (`chat-slow-pulse`) even while `connState` stays `on`; the watchdog does not close the socket. `HEARTBEAT_STABILITY_MS` (5s) only resets reconnect backoff after a stable OPEN; half-dead close is ping 15s + pong 10s or inbound silence 60s. A mid-stream WebSocket close latches the same pulse immediately. The pulse stays through reconnect `get_messages` refill and clears when live tokens resume or refill finishes. A reconnect `get_messages` of one session does not skip another session's settled stall refill. Steering delivery is transactional: a steer whose transformed `MessageEnd` already reached agent state is withheld after a later listener failure, and only the never-emitted tail returns to the queue head in FIFO order.

**TUI:** conversation + composer + status; overlays for settings, goal, todo, workflow, code-review, sessions/tree, jobs/activity/IRC, processes, side chat (`/btw`), live STT. Inline images via Kitty or iTerm2 (`terminal_images.rs`); Sixel is detected only, not rendered. File HTML preview is Web-only (no HTML sandbox in the terminal pager).

Desktop (≥1280), tablet (≈820), and mobile (≤720, drawer via the single ☰ header menu) are first-class layouts. `/web` pins the composer with `html, body, #root` at `100dvh` (and `height: 100%` where `dvh` is missing) so the footer stays at the visual bottom at 390, 820, and 1280. Both pages' top brand nav (`nav.brand-switch`, one 44px segment per page) keeps the current page in accent with `aria-current="page"` and links the other page: `/web` shows `Web` current plus the same-host `/chat` entry (`#chat-console-link`), and `/chat` shows the same-host `/web` entry (`#web-console-link`) plus `Chat` current. The idle composer is 44px tall (`/` 📎 🎤 ◉ Live are 44×44 and do not stretch when the placeholder wraps; Send is 44px tall) on `/web` and `/chat`; the sidebar New session button (`#sidebar-manage-btn`) and the center composer (`#prompt-input`) are 44px at desktop and mobile.

**Transcript pin:** `/web` main, `/chat` SessionView and BroadcastConversation, the hunk-review thread dock, and Side chat share `createScrollPin`. Remaining 0 stays glued; remaining 1 unpins and never writes `scrollTop`; a container `clientHeight` growth that clamps the viewport to the new bottom (gap 0) keeps follow, while a genuine scroll that leaves the bottom in both the current and the remembered geometry still unpins. Session, hunk, or side-chat tab switch may `forcePin`. Showing a previously hidden hunk-review thread dock (narrow Thread tab) also `forcePin`s to the tail. Incoming messages, accepted follows, stream deltas, and the active surface's projection compensation use `pinIfPinned` only. Hidden surfaces never write the shared `#transcript` scrollTop. Live `follow` is the pin controller, not 80px geometry. The `/web` transcript adds a 44px transparent-circle "Scroll to bottom" overlay (`button.transcript-scroll-bottom` inside the `.transcript-scrollport` wrapper) that reuses `forcePin`; desktop reveals it on hover/focus-visible, touch (`pointer: coarse` / `hover: none`) keeps it visible, and an open code-review panel hides the whole scrollport out of paint and tab order.

**Reply actions:** `/web` main transcript and the subagent history modal — every settled assistant reply carries a shared `ReplyActions` strip inside the reply row's left reserved band at every viewport width, fully left-outside the answer body and intersecting the first text line from the row top (`top: 0`, no negative offset, inside the row's `content-visibility` paint box). The strip stacks vertically (`flex-direction: column`): the favorite star keeps the established `assistant-star-toggle` DOM, classes, and `data-entry-id`, then copy raw markdown (`data-reply-action="copy-markdown"`) and save raw markdown as `.md` (`data-reply-action="save-markdown"`). Copy/save render on every reply that has the strip — never gated on the authoritative `entryId` or a wire timestamp (the subagent history modal renders the strip without the favorite, since it has no session scope); only the star button waits for the `entryId`, and an id still awaited from `get_messages` hydration shows no star and no saving status. In the `/chat` SessionView the same strip renders on settled replies; the star appears whenever the row carries a real `entryId` — first-mount and restored rows already do, and a live reply gets it from the typed `turn_terminal`-triggered authoritative hydration (one `get_messages` merged against the request cut, guarded by terminal/runtime/connection identity) — so live/synthetic ids show copy/save only. Collaboration guest rows show copy/save for live replies; the star appears only on an authoritative restored entry with a real id — a fresh join with the original private invite restores the new document snapshot with real ids, enabling star toggle plus copy/save under the same filename — and live replies never show an immediate star. Side chat, file conversation, the code-review TL;DR pane, and the Broadcast channel log carry copy/save only: no star chrome and no fabricated `entryId`. The Broadcast log stores one row per real assistant reply; its source is that reply's raw `sourceMarkdownFromBlocks` (the stored log text is never clipped to the 8,000-character display bound) and its save filename uses the settled reply's wire END timestamp (`generatedAt`), never the local channel-log append clock. The raw markdown is `sourceMarkdownFromBlocks` — the verbatim concatenation of the reply's `text` blocks in wire order, never DOM-scraped and never trimmed. Save downloads `<summary>-<stamp>.md` (`reply-<stamp>.md` without body text), named from the reply's own stable wire timestamp (`AssistantMessage.timestamp`: captured at `message_start`, canonical at `message_end`, preserved through the no-`message_end` finalize; never the browser clock) with the file bytes exactly that source. A reply without a usable wire timestamp fails ONLY the save — the app's central error toast fires and copy stays available (as does the favorite where the strip has one). Fine pointers use 20px-wide, 24px-tall glyph buttons resting at opacity 1 with the row's `padding-left` at 26px (hover/focus give a background/outline, never an opacity reveal); `(pointer: coarse), (hover: none), (max-width: 720px)` uses 44×44 buttons with the row's `padding-left` at 50px and a 132px reply `min-height` when the star is present (72px desktop); a strip without the star reserves 88px (48px desktop). The accessible Star/Unstar name and `aria-pressed` stay; the visible label is hidden at every viewport and the glyph stays visible. One ☆/★ control toggles it and a starred reply shows ★, keyed by that `entryId` so live and restored replies share one star. The star set is browser-local `localStorage` under the encoded `rpi-web-reply-stars:<listener authority>:<session id>` key (the same two-part scope as session preference) with no origin-wide fallback, so identical entry-id strings in another listener or session never share stars and nothing is written to the server or shared across devices. Starred replies render in a right-side `.starred-reply-minimap` beside `#transcript` inside `.conversation-with-minimap` — a reserved flex column, never an overlay over reply text, and an empty set renders no rail; clicking a jump scrolls to that reply even when it is offscreen (parking/restoring the windowed transcript) and collapses the rail. At ≤720px the rail is a compact 44px column that expands to 140px.
  Each minimap row carries two separate controls: the preview (jump, stamped with the authoritative entry id) and a separate explicit 44×44 unstar action that only toggles the star off — it never jumps and never collapses the rail; the rail itself collapses/expands through its ★ count toggle. **Jump top-stability contract:** a minimap jump click lands the target reply with its viewport-relative top at |top|≤1px (a negative overshoot above the viewport top is drift, not a landing) within a bounded frame window and must hold |top|≤1px, the target mounted with a UNIQUE entryId match and a non-empty `data-item-id` (both re-read through the `entryId` on every frame, never a stale pre-click id), for the next 120 animation frames — any |top|>1 drift, unmount, lost id, or duplicate target is a regression; the landed target survives the rail fold without rolling back, the user's wheel always takes back over a parked (jumped) view, and the same contract holds after appends to the same session, after reload, and for consecutive clicks on desktop and mobile.

## Agent loop and context

- Turn-stable model selection: `(provider, model_id)` captured at turn start. `/web` header `#model-select` writes that pair on the current session (`set_model` → JSONL `model_change`); `settings.json` `defaultModel` is new-session start only. A settled pick survives refresh, reconnect, and later `get_state` that still names the previous model. A catalog gap still shows the session's `provider/id`, never `model…`. A selection made during a live turn is a next-turn selection: the running turn keeps the model and generation it was admitted with, and the next admission applies the pending refresh (an idle selection refreshes immediately); a `task_spawn` while that selection is pending and the turn is live is rejected as busy (`SessionAlreadyProcessing`) instead of inheriting the pre-selection generation.
- Automatic context compaction; threshold compaction runs before the first provider request, including an automatic Goal continuation that begins without a second user message; `/compact` LLM path and `/snapcompact` deterministic archive; the lossless authoritative transcript keeps all pre-compaction messages and inserts the compaction summary marker in place, while model context is compacted separately.
- Web compaction activity follows accepted runtime-scoped start/end events and subscription cuts; a completed compaction clears its badge without another state poll. Local request generations and runtime identities prevent stale settlement from clearing newer work. The badge uses the existing theme accent and honors reduced motion.
- Rewind / named checkpoints; lossless sidecar before compaction commit
- Session tree, branch, fork, clone
- Steering queue while streaming; follow-up after yield; `/queue send` aborts then prompts remaining steering; `/queue cancel`
- Doom-loop recovery; session TTL
- Handoff summaries (`/handoff`); Web Hand off is the envelope into a new same-cwd session and switch; `--prose` is TUI/REPL only. Web `session_handoff` calls `generate_handoff()` in `session_runtime_manager.rs` (not `generate_handoff_with_prose`); `session_handoff` is not in `LONG_OP_TYPES`, so the Web pending timeout is `DEFAULT_COMMAND_TIMEOUT_MS` (30_000).
- Session move: relocate a saved native session file to another existing directory and record the new cwd as the session's working directory — TUI `/move <absolute-existing-directory>` for the active session (queued while a turn streams, cutover at settle), Web "Move session" (`session_move`) from the session sidebar for unloaded or idle active rows, with the idle active session staying active and rebound to the destination. The Web session list scrolls independently of the fixed Sessions header. On phones, opening the header module menu closes the Sessions drawer; the menu is bounded between the header and composer and scrolls inside its own panel.
- AGENTS.md / CLAUDE.md project context (unless `--no-context-files`)
- Prompt templates; system prompt assembly
- Config profiles (`--profile` / `PI_PROFILE`)
- Settings JSON or sibling TOML; schema catalog; hot reload via filesystem notify (Linux inotify, macOS FSEvents, Windows ReadDirectoryChanges); debounce then `Application::reload()`; invalid reload keeps last-good
- Atomic settings generations and trust-gated project resources
- Retry: same-model transport retries in `pi_ai`; session auto-retry in `Session`; ordered model/provider failover via `retry.fallbackChains` (`retry_fallback.rs`) keyed by role, exact selector, or provider wildcard; gated by `retry.modelFallback`
- RPC `message_update` (`modes/rpc.rs` `project_message_update`): `message` is assistant metadata only (`role`, `api`, `provider`, `model`, `responseModel`, `responseId`, `diagnostics`, `usage`, `stopReason`, `errorMessage`, `rawStopReason`, `timestamp`) and never carries `content`. One nested `assistantMessageEvent` per record: `content_index`, `delta` fragments, complete block `content` at `text_end` / `thinking_end`, `tool_call` at `toolcall_end`, full assistant `message` at `done` and full `error` at `error`. The optional metadata fields and an empty `diagnostics` are omitted. Clients accumulate deltas; `message_end` is the authoritative full message, with no partial-message compatibility payload.

## Built-in tools

`TOOL_NAMES` in `crates/pi-coding/src/tools.rs`:

**Workspace:** `read`, `write`, `edit`, `ls`, `grep`, `find`, `glob`, `bash` (danger-mode in-process bash is scheduled one-at-a-time per durable session: overlapping same-session bash queues behind the holder without a time bound and runs once the lock frees — the queue wait is abort-responsive and never fails the run; coordinator and each durable subagent own a distinct lock and do not queue behind each other; confined and PTY bash never take that lock). Timeout/abort reaping is rooted at the dedicated brush TID after a TID+start-time identity check. Grep directory traversal is best-effort only for vanished entries: it skips directory-enumerated entries whose post-listing child open reports `OpenEntry` + `NotFound`; permission, identity, and every other error still fail the walk. Grep also detects reachable child git repositories during the walk — a `.git` directory or worktree file switches the active ignore context to that repository's own rules until the subtree exits and restores the outer context for siblings — while non-repo `.gitignore` files stay inert and already-ignored directories are never entered or probed.

Bash `input` accepts a string or JSON `false` for no stdin; other non-string values remain invalid. Argument validation names a bounded schema-declared field and its received JSON type without exposing argument values. Nonzero-exit, timeout, and launch failures stay typed errors (`error` remains `true`) carrying `details` `{ requestedCwd, stage: 'launch'|'timed_out'|'non_zero_exit', exitCode: integer|null }` — `requestedCwd` is the authorized workspace root the tool was built with, never the effective process cwd; `launch` is the coarse classification for runner failures and can fire after the process launched, so no stage says whether the command executed; abort/cancel failures are never classified into these stages. The Web tool card parses this typed diagnostic and strips the model text's `[bash diagnostic] stage=… requested_cwd=…` trailer so the status renders once instead of duplicated; invalid details keep the original error text.

Glob `path` is resolved lexically inside an authorized workspace root; symbolic links in the explicitly requested glob target path are followed only through the retained root authority (physical target confined to that root and re-checked against denied/private paths, identity pinned), entries are hidden when either the lexical or the physical coordinate is denied/private, child symlinks stay skipped and are never traversed, and other tool filesystem APIs keep strict no-follow behavior.

## Extensibility

### Host hooks (`settings.hooks`)

Events: `pre_tool_call`, `post_tool_call`, `session_start`, `session_end`, `turn_start`, `turn_end`, `pre_trust_decision`. Argv only (no shell). JSON stdin; blocking JSON stdout only for `pre_tool_call` and `pre_trust_decision`. Default fail-open; `failClosed` blocks/denies on error. Matcher: exact subject equality only (`read` does not match `read_file`). `session_start` fires on the first agent turn (`begin_run`), subject `"session"`, not at process start.

### Extensions (`pi-extension.json`)

Process executables or in-process QuickJS (`.js`/`.mjs`). Capabilities: `commands`, `tools`, `event_hooks`, `message_renderers`, `provider_metadata`, `provider`, `session_actions`, `ui`, `overlays`. Project extensions load only when the project is trusted. QuickJS: dedicated thread, 64 MiB, no Node globals. QuickJS rejects `message_renderers` and `provider_metadata`. `/overlay` addresses registered overlay ids.

### Packages (`rpi install`)

Local path or git (`https`/`ssh`/`git:`). Resources: extensions, skills, prompts, themes. `npm:` is rejected here. Project packages require trust.

### Plugin marketplace (`rpi plugin`)

Standalone `pi-extension.json` packages into `<agent_dir>/extensions/<name>/`. Sources: directory, tar/tgz, HTTP(S) archive, `owner/repo` or `owner/repo@ref` GitHub, git URL (`http`/`https`/`ssh`/`file`/`git+…`), `npm:` (sha512 `dist.integrity`, HTTPS→HTTP tarball refused when registry is HTTPS). Load requires an exact `Trusted` trust-store decision. Trusted command plugins run from TUI `/name` and `/run` and from the Web Command picker / composer (RPC `run`).

### Skills, prompts, themes, MCP

- Skills: `SKILL.md`, `skill://` confined reads, selector ranking, optional classifier re-rank
- Prompt templates and JSON themes (packages or `--prompt-template` / `--theme`)
- MCP client in-session; `rpi mcp list|import` from Claude Desktop or Cursor

## Voice

Two configs (`live.mode`: `stt` / `realtime`; `docs/src/user-guide/live.md`). The Web surfaces both voice controls at once (independent of `live.mode`); the terminal implements STT only and does not implement WebRTC.

- **TUI STT:** `live.enabled` + `live.mode: "stt"`; `/live` hold Ctrl+Space; whole-utterance transcript lands in the composer (no interim streaming). OpenAI-compatible `{sttBaseUrl}/v1/audio/transcriptions`. Limits: 30s retained mono 16 kHz, 10s no-speech watchdog, 30s request timeout, utterances shorter than 250ms skipped. HTTPS unless `live.allowInsecure`.
- **Web STT RPC** (`stt_rpc`) for composer dictation. Hold-to-talk destination is captured at pointer-down / `startRecording` as `MainComposer` or `SideChatTab(id)` (`captureSttRecordingDestination` / `planSttTranscriptRoute` in `useSttRecorder.ts`; `startMainSttRecording` / `startSideChatSttRecording` / `onSttTranscript` in `App.tsx`), not from completion-time `activePanelRef`. Main footer while Side chat is open stays on main. There is no `insertNow`: a live dest tab always awaits `side_chat_switch(dest.tabId)` (`applySideChatSttInsert` `awaitSwitch`; `settleSideChatSttAfterSwitch` / `resolveSideChatSttInsert` in `SideChatPanel.tsx`); insert only when ACK `active === dest.tabId` and dest is still in `tabs`. Typed `discardClosed` is only panel closed, dest gone, seq superseded, or ACK `active !== dest` (`SIDE_CHAT_STT_CLOSED_TOAST`); never auto-submits on the main composer. Switch/insert errors toast `side chat switch: … (session=… tab=…)`. Catch uses `planSideChatSwitchCatchToast` + `isToastOwnedRpcError`: an already-owned toast stays silent (no second toast); otherwise display once then `toasted: true`. Unmount `!live` does not overwrite `kind: 'error'` (`finishSideChatSttInsertAfterAwait`). The footer `#mic-btn` (aria-label Hold to talk) is independent of Live; `useSttRecorder` exposes a phase model — `starting` is only the getUserMedia acquire, `recording` covers record through stop, `transcribing` the upload, and a synchronous `isBusy()` is true for every non-idle phase.
- **Web realtime:** the footer `#live-btn` (`Start live voice` / `Stop live voice`) is independent of `live.mode` and starts whenever `live.realtimeConfigured` is true; WebRTC create-call + `oai-events` data channel; frameless v3 session config (instructions, output voice, delegation); model selection is proxy-owned (`realtime.ts` omits `model`). The call is torn down when `realtimeConfigured` disappears, not when STT mode is selected; while hold-to-talk is in any non-idle phase `#live-btn` is disabled and its click sends no RPC, and while a live call is up or setting up `#mic-btn` is disabled. While the call is up, a live transcript overlay (`#realtime-transcript`) sits above the composer with connection-state (`#realtime-conn-state`) and preview text. A finalized user transcript lands in the composer as a draft and does not auto-send. Delegation flush toasts `Voice draft ready`, not that an agent started.

## Platforms and release

Release matrix (`.github/workflows/release.yml`): CLI `x86_64-unknown-linux-gnu` and `aarch64-unknown-linux-gnu`; the same tag publishes Linux amd64 and arm64 desktop packages plus one Android APK covering `armeabi-v7a`, `arm64-v8a`, `x86`, and `x86_64`. Android release signing is fail-closed: the APK is signed only from the four `ANDROID_RELEASE_*` secrets, the signer must equal the pinned `ANDROID_RELEASE_CERT_SHA256` repository variable, and the checked-in debug keystore never signs a release — a missing, debug-signed, or mismatched APK fails the release. macOS CLI and desktop artifacts are temporarily unavailable from tagged releases. Windows artifacts are not published. iOS is not published. Settings watch uses notify: Linux inotify, macOS FSEvents, Windows ReadDirectoryChanges. Windows has no OS confinement.

**Desktop Electron:** [`crates/pi-cli/desktop`](crates/pi-cli/desktop/README.md) hosts `/web` or `/chat`; without a runner override it starts and owns a release `rpi` on a selected plaintext loopback port and waits for `/status`. Explicit `--runner` / `RPI_DESKTOP_RUNNER` / `settings.json` `runnerUrl` selects connect-only mode; **Runner → Use local runner** drops a stored URL and starts the owned loopback process again. `--route web|chat` and the Runner menu select the route. A sandboxed, origin-scoped preload exposes only native-menu action subscription/capability registration, not Node or filesystem access. `/web` registers workspace/session creation, settings, attachment and stop actions subject to page state; `/chat` registers workspace/settings and mounted-session attachment/stop, but native New session stays disabled. Quit stops only the owned child (SIGINT, then bounded SIGKILL); external runners remain running. Self-signed listener certs use a remembered certificate exception (`trusted-pins.json`, exact origin + fingerprint), not identity pinning. `package-deb.sh` bundles the release runner and Electron into an amd64 or arm64 `.deb` (`/opt/rpi-desktop`, `/usr/bin/rpi-desktop`); `package-mac.sh` and `package-win.ps1` remain development packaging scripts that the tag release no longer runs. development requires a release runner and graphical Electron prerequisites. Desktop UI and packaged acceptance are **PENDING**; headless Electron launch attempts **FAILED** (exit 1). Not in the GitHub release matrix.

**Desktop local sign-in:** Managed-local mode offers **Runner → Sign in / configure provider…** and a native startup-failure action. A separate app-owned sandboxed window runs the existing provider prompts through `rpi login --json`; remote pages cannot invoke its bridge. One owned attempt is allowed, browser links require an explicit action referencing the current HTTP(S) authentication event, and credentials travel through stdin. Only credential-store completion plus child exit zero triggers one managed startup retry; stored credentials are not proof of provider access. Cancel, window closure, quit and remote transition tear down the owned attempt; cancellation does not undo already-persisted credentials. Fresh empty-config native onboarding remains **PENDING**, not established by compilation or authored tests. See the [desktop sign-in contract](crates/pi-cli/desktop/README.md#sign-in--configure-provider).
