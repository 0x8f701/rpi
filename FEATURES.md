# rpi core features

Inventory of shipped product capabilities in the current tree. Sources: `README.md`, `docs/src/SUMMARY.md`, `crates/pi-cli/src/args.rs`, `crates/pi-cli/src/interactive_commands.rs` (`BUILTIN_COMMANDS`), `crates/pi-coding/src/tools.rs` (`TOOL_NAMES`), `crates/pi-cli/src/modes/listen.rs`, and the pages under `docs/src/`.

The executable is `rpi`. Runtime dir: `PI_CODING_AGENT_DIR` > `RPI_HOME` > `~/.rpi` (`%USERPROFILE%\.rpi` on Windows). Project dir is `.rpi/`.

When a change adds, removes, or changes a user-visible capability, update this file in that same change (`AGENTS.md` Documentation Standards). Inventory E2E: `bash E2E.d/features.sh` (map: `bash E2E.d/features.sh list`).

## Surfaces

| Surface | How it is selected |
|---|---|
| Print | `-p` / `--print`, or non-terminal stdin/stdout **and** a non-empty prompt (`lib.rs` `main_run`). Empty prompt stays interactive. |
| JSON event stream | `--mode json` |
| JSONL RPC | `--mode rpc` or `rpi rpc` |
| Line REPL | interactive, but not a full terminal pair |
| TUI | both stdin and stdout are terminals (`crossterm` + `ratatui`, inline / no alt-screen) |
| Web listener | `--listen` HTTPS/WebSocket; never starts TUI/REPL; positional prompts are rejected |
| ACP | `rpi agent stdio` / `rpi agent serve` (Agent Client Protocol) |

TUI and Web share the same session/RPC core. Platform-only gaps are called out below.

`--listen` HTTP paths (`listen.rs`):

| Path | Role |
|---|---|
| `/web` | operator SPA; Teams liveness probe (`GET` 200 `text/html` with rpi markers, `team.rs`); header ☰ (`#sidebar-toggle-btn`, `panel-toggle`) opens the right-side menu whose Chat item is same-host `/chat`; a close (1006/1008), heartbeat timeout, send failure, or bootstrap failure covers the whole page (`#reconnect-overlay`, spinner + `连接断开，正在重连…`) until reconnect bootstrap finishes; application ping every 5s; a ping dies only after 10s with no inbound frame at all (any post-ping frame, including a large transcript, counts as alive); server idle kick 30s; reconnect backoff 250ms–5s and heartbeat/stale close resets that delay immediately; wake of an OPEN socket always pings (application-message age is not a tear-down); hidden-tab heartbeat timers do not retire the socket; a background-aged outstanding ping and silence timer are dropped and a fresh probe is sent; a truly dead socket still dies on the 10s missed-pong path after the page is visible; refill/session_list bootstrap failures retry twice at 1.5s then fail closed so the overlay stays; header chip remains a compact pulsing warn mark on connecting/reconnecting (`chat-slow-pulse`, `aria-label` Reconnecting…); raw error only for token_required |
| `/chat` | LAN ChatApp (projects, runner invite, mapped sessions); header ☰ (`#chat-workspace-menu-btn`, same `panel-toggle` control as `/web`) opens a menu whose Web item is same-host `/web`; selected-runner connecting/reconnecting/offline uses the same `#reconnect-overlay` over the workspace shell |
| `/ws` | WebSocket control plane |
| `/rpc` | JSON-RPC POST |
| `/status` | listener status |
| `/upload/video`, `/upload/pdf`, `/upload/tmux-file` | authenticated composer attachment extract; tmux-file writes a temp path and pastes it into a tmux session |
| `/collab/ws/<room>` | collaboration guest room (`collab_room_id`) |

Pairing: banner prints `{origin}/web` or `{origin}/web#{token}` (`lib.rs`). Tokenless loopback is optional; non-loopback requires `--listen-token-file` unless `--listen-allow-insecure-remote`. Wildcard binds need `--listen-advertised-origin`. Missing token on a required listener opens `TokenPairingCard` (`token_required`), not an unauthenticated reconnect loop. A stored token whose `/ws` handshake never opens still auto-reconnects unless an authenticated `POST /rpc` probe confirms HTTP 401.

**Composer attachments** (`attachments.ts`, four kinds; prompt frame cap `MAX_RPC_MESSAGE_BYTES` 4 MiB):

| Kind | Wire |
|---|---|
| image | `ContentBlock::Image` on `prompt.images` |
| video | `POST /upload/video` → ffmpeg JPEG frames + instruction text (never raw video on the prompt frame) |
| pdf | `POST /upload/pdf` → pdftotext + instruction text |
| code | UTF-8 text fenced into `prompt.message` |

Other binaries and invalid UTF-8 are rejected at intake with a visible reason. `/web` and `/chat` image and code chips include Send to terminal (`POST /upload/tmux-file`): allowlist png/jpeg/gif/webp/pdf and UTF-8 text/code, 8 MiB cap, temp file deleted after 5 minutes; the path is pasted into the overlay runner's tmux session and toasted. The upload posts to the overlay destination's runner authority (typed `runnerId` + session), not the current page host. The `/chat` tmux overlay soft-key bar has an Upload control next to Ctrl that posts the same `/upload/tmux-file` endpoint to the overlay session and toasts the returned path.

**Composer interrupt:** `/web` and `/chat` ■ Stop (pointerdown) flip the footer to stopped (Send) immediately, before abort RPC resolves, then send RPC `abort` for the displayed session, including while a tool such as bash is running. Live `isStreaming=true` events and `get_state` cannot re-arm Stop until abort settles or a new `turn_started`. After abort, `get_state` confirms idle. The tap is not gated on a client streaming flag. Abort RPC failures toast. Toasts stack above `--app-footer-height` so they never cover Stop. TUI Esc/Ctrl-C uses the same `Application::abort` (bash then agent; in-flight brush bash is killed, not waited out).

**Composer Enter:** `/web` and `/chat` composers send on Enter (Shift+Enter stays a newline). `#prompt-input` and `/chat` composer textarea are 16px at every width so iOS Safari does not auto-zoom a 13px field and steal taps from the composer, Stop, and the steering tray. Android GBoard may leave `isComposing: true` on the send key after `compositionend`; that Enter still submits. `beforeinput` `insertParagraph`/`insertLineBreak` submits when keydown did not. Enter always requests `prompt`; `planComposerSubmitKind` converts to `steer` only from the session streaming ref. `/web` submit claims a `composerSendingRef` that spans `sendCommand` ACK for dispatched sends; validation and local panel actions that do not send release immediately.

**Steering:** `/queue`; modes `all` / `one-at-a-time` (`QueueMode` kebab-case). Web composer tray: one 36–44px row per queued message (label + ellipsized preview + send now / cancel), on one composer status row (activity state left, queue right) on `/web` and `/chat` including 390px (footer overflow stays visible so the tray is not clipped). While a turn is processing, `/web` and `/chat` composer submit send `steer` (not `prompt`) from `streamingBySessionId` / turn-level live streaming (`turn_terminal` clears it; inner `message_end` does not); a typed `session_processing` prompt rejection resends the same content as `steer` once. Optimistic tray rows survive empty `get_state` until a live `queue_update`. Live sequence gaps resubscribe once and probe `get_state` (auxiliary, coalesced); an idle snapshot then requests one settled `get_messages` refill. `busy_capacity` catch-up and reconnect-refill failures stay silent. Queue shrink is not treated as consumption. Send now (`queue_send_now`) aborts the in-flight turn, waits until idle, then prompts the combined steering as a new turn (it does not re-enqueue via `steer`). The tray clears only on authoritative `queue_update`. Cancel of an already-consumed row is a no-op success, not a stuck button. A steer that exceeds the 4 MiB RPC frame is refused before the composer clears, with the size-limit toast; other steer RPC failures toast the server reason and drop that optimistic row. A live sequence gap or `get_state.isStreaming === false` while a streaming assistant is still painted refills `get_messages` so a missed `turn_terminal` cannot freeze the transcript mid-reply. While a turn is streaming, 5s without a sequenced event `get_state`s (then that same refill) and paints the `/web` footer activity strip plus header chip as pulsing Reconnecting (`chat-slow-pulse`) even while `connState` stays `on`; the watchdog does not close the socket. `HEARTBEAT_STABILITY_MS` (5s) only resets reconnect backoff after a stable OPEN; half-dead close is ping 15s + pong 10s or inbound silence 60s. A mid-stream WebSocket close latches the same pulse immediately. The pulse stays through reconnect `get_messages` refill and clears when live tokens resume or refill finishes. A reconnect `get_messages` of one session does not skip another session's settled stall refill.

**TUI:** conversation + composer + status; overlays for settings, goal, todo, workflow, code-review, sessions/tree, jobs/activity/IRC, processes, side chat (`/btw`), live STT. Inline images via Kitty or iTerm2 (`terminal_images.rs`); Sixel is detected only, not rendered. File HTML preview is Web-only (no HTML sandbox in the terminal pager).

Desktop (≥1280), tablet (≈820), and mobile (≤720, drawer + hamburger) are first-class layouts. `/web` pins the composer with `html, body, #root` at `100dvh` (and `height: 100%` where `dvh` is missing) so the footer stays at the visual bottom at 390, 820, and 1280. `/chat` workspace ☰ (`#chat-workspace-menu-btn`) is 44×44 from 721px and on the ≤720 drawer; the bar (`z-index: 30`) and menu (`z-index: 31`) stay above the tmux overlay (`top: 44px`, `z-index: 20`). Esc closes the ☰ first; pointer-down outside dismisses it. The idle composer is 44px tall (`/` 📎 🎤 are 44×44 and do not stretch when the placeholder wraps; Send is 44px tall) on `/web` and `/chat`.

**Transcript pin:** `/web` main, `/chat` SessionView and BroadcastConversation, the hunk-review thread dock, and Side chat share `createScrollPin`. Remaining 0 stays glued; remaining 1 unpins and never writes `scrollTop`. Session, hunk, or side-chat tab switch may `forcePin`. Showing a previously hidden hunk-review thread dock (narrow Thread tab) also `forcePin`s to the tail. Incoming messages, accepted follows, stream deltas, and the active surface's projection compensation use `pinIfPinned` only. Hidden surfaces never write the shared `#transcript` scrollTop. Live `follow` is the pin controller, not 80px geometry.

## Sessions and import

- Native Pi v3 JSONL under the agent session root, namespaced per checkout
- Independent loaded sessions: each owns application state, dispatcher, publication, and command execution; switching the displayed session changes only the view target
- Web switch (`/web`): a registered runtime is reused only when its owner has no published terminal state, the application is not cleaned, and the recorder writer is available — registry membership alone is never health. A registered primary whose owner task aborted still fails closed with `runtime_unavailable` (`owner_stopped` / `application_closed` / `writer_unavailable` / `retrying`). Cold, warm-continuity, and resync cuts attest a `messages` array from the retained-writer projection (empty is valid). A `session_resync` cut applies those messages even when its events are a high-watermark replay-buffer tail (not a 1..watermark chain); the client binds instead of resubscribing from cursor 0 and painting the empty-session hint. Overlapping subscribe snapshots for the same runtime identity share one in-flight cut (the second caller waits for or shares that result). A typed `snapshot_in_progress` error retries subscribe once before rollback. A later `subscription_error` matching the pending target, or a 15s silence waiting for that cut, rolls back to the source transcript and never clears it. Reconnect on every socket generation keeps last-good transcript rows visible and marks the connection live as soon as the displayed runtime is subscribed at its stored cursor (live frames apply incrementally); `get_messages` refill runs in parallel with `session_list` and never blanks the transcript while it is in flight. A saved catalog target already on screen is not switched again. The 15s cut timer pauses while that refill is in flight and only fires after 15s of silence. Mid-turn streams keep delivering on the new socket using the server assistant id; a turn that finished while away loads the settled transcript. A warm-continuity cut that would bind authority with empty merged durable history confirms once via `get_messages` before bind. Bootstrap switch of an explicit saved target toasts on failure and retries that switch once after the ready gate; a failed saved restore never writes the listener primary into the session preference. Catalog `already_imported` rows keep the foreign display name as `sessionId`; open/restore/`get_messages`/subscribe use the native file UUID (`nativeSessionId` + `nativePath`) and never treat `session_info.name` as the runtime id. When an `already_imported` alias and the native rpi copy both match the displayed runtime, the catalog active marker is the native copy.
- Persisted `get_messages` / ColdFull snapshot project the recorder's retained writer plus pending records; a tree-load failure is `transcript_unavailable` (never success-with-empty, never a path reopen of the live append-only file). A loaded runtime whose retained tree has durable messages but the active leaf does not resolve re-projects once from that writer's parsed leaf or fails closed as `transcript_unavailable` — never `success` with `messages: []`. Genuine new/empty sessions and an empty active branch remain valid empty. Loader skips (id-less records) and undecodable message payloads are counted and returned on `get_state` as `skippedIdless` / `undecodableMessages`; those drops are never treated as a genuine empty transcript. Web reconnect and runtime invalidate keep last-good durable rows until `close_session`; an empty refill cannot wipe them. Long transcripts (300+ messages, including payloads above the old 24 MiB snapshot/WS cap) travel on the 240 MiB outbound budget; the Web surface still renders a bounded window.
- `--continue` newest native session; `--resume` / `/resume` native or foreign
- `new_session` auto-creates a missing absolute cwd (`prepare_or_create_operator_directory`)
- Import / convert: Pi, OMP (rotation chains), Codex, Claude, Grok/Hyper, Droid via agent-loader; exclusive create + `import_lineage`; Cursor Agent is not convertible. OMP rotation `customType: "handoff"` custom messages stay out of the native import file.
- Unified catalog with source badges; first open of an external session converts once; when both the `already_imported` alias and the native copy are listed, the active marker is the native copy
- HTML export, clipboard copy, GitHub gist share; `/share --encrypt` is AES-256-GCM via PBKDF2-HMAC-SHA256 (210,000 iterations), layout `salt(16) || nonce(12) || ciphertext+tag` (`encrypt.rs`)
- Web archive: `session_delete` with a 5s undo (`session_restore`); rejects the current session and busy loaded secondaries
- Collaboration rooms: host `/collab`, guest `/join` (full-control `#c=` / view-only `#v=`)

## Goals, todos, orchestration, workflows

- **Goal:** durable objective, token budget, pins, journal, pause/resume/complete/drop. A refused `/web` or `/chat` create or pin keeps the typed draft until the ACK succeeds.
- **Todo DAG:** `/todo` panel; durable child sessions; markdown ingest. Web child create/send/add-task/hub claim exclusive refs and clear a matching draft only after ACK.
- **Orchestration:** subagents, jobs, soft budgets, IRC hub mailbox, `task`/`hub`/`yield`. Subagent details sheet: pinned header; body is the only scroll region; status, Task, Latest activity, and Recent transcript stack in normal flow so wrapped Task text never overlaps later sections. Recent transcript is compact labeled rows: assistant text keeps the `assistant` tag and wraps up to two lines (tap expands, still bounded); each tool call is one merged row `[bash] command · ok` (not an `assistant` tag, not a separate result row), collapsed by default to a one-line preview (`nl · proposal_store.rs` for `nl -ba …/proposal_store.rs`; pipelines show the first verb) and expanding to the full command. Transcript Task cards fold Goal/Constraints/Contract behind a one-line preview expander and child rows show one action line (live activity, else result, else the assignment's first line) with the full assignment in an assignment fold. Web Subagents spawn claims a `busyRef` before `task_spawn` and hub send claims a `hubSendingRef` before `hub_send`; drafts clear only after a successful ACK whose current trim still matches.
- **Durable persona state:** a persona's root `<agent-dir>/personas/<name>/` holds `persona.md` (definition), `memory/entries.jsonl` (its `memory` tool), `sessions/<agentId>.jsonl` (archived child transcripts, loaded newest-first as continuity), and `skills/<name>/SKILL.md` (learned persona-local skills). `/persona reset` clears memory, sessions, and learned skills and keeps `persona.md`; `/persona remove` deletes only `persona.md`; `/persona remove --purge` deletes the root. Every activation is a fresh child run with a new id; durability comes from those files, never from a resident process. Task-spawned children inherit the parent's full `WorkspaceRoots` (cwd plus `--add-dir` roots).
- **Persona-local learned skills:** a persona that explicitly declares `learn_skill` and permits `write` in `capabilityCeiling` receives the persona-only `learn_skill` tool; it writes `<persona-root>/skills/<name>/SKILL.md` through the retained persona capability root and never touches the global or project skill trees. The learned skill is reported as available beginning with the next spawn or revival, is always autoloaded into that persona's prompt, shadows a same-named shared skill only inside that persona, and resolves through `skill://<name>`.
- **Personas / roles / agent definitions:** `/persona`, `/role`, `/agents`. `/persona run <name> <assignment>` spawns through the ordinary orchestration path. Web save/run/remove/select/clear claim a `busyRef`; Run keeps the assignment unless a job is produced and the current trim still matches.
- **Workflows:** concurrent isolated worktrees (`worktree` / overlayfs / none), plan + Todo-DAG execution. The mandatory planner Todo tool survives Application attachment and resource reload even when interactive `orchestration.todo` is false. Web create claims a `creatingRef` and IRC send claims an `ircSendingRef`; drafts clear only after ACK when the current trim still matches.
- **Loops:** recurring prompts (`/loop`); Web Loop panel is that surface, not the Processes panel. Web create claims a `busyRef` lock and clears the prompt only after a successful `loop_create` whose current trim still matches the sent payload.

- Per-file Explorer Ask (Web dock + Android; the TUI has none): a file tab's Ask surface (`FileConversationDock`; Android `FileConversationView`) drives `file_conversation_open/prompt/snapshot/abort/close` (`file_conversation.rs` `FileConversationEngine`) on a read-only side-chat fork (`SideChatController` `SideChatToolMode::ReadOnly`), so tool calls stay in the dock and never reach the main transcript; Web Explorer and `/btw` share the `ConversationEntries` renderer, Android renders the same `SideChatEntryWire` schema through its native rows. Snapshots poll at 500ms while streaming / 1500ms idle (Android 2000ms); ■ Stop sends `file_conversation_abort`. One conversation id per tab (`FILE_CONVERSATION_MAX_OPEN` 8 = `FILE_EXPLORER_MAX_OPEN_TABS` 8), owner-stamped (runtime epoch + recorded-session identity + cwd; superseded owners retire); hiding the panel retains tabs, drafts, selections, and snapshots, while an explicit tab close or slot eviction/session drop sends `file_conversation_close` and a reopened tab starts a NEW conversation. The backend validates the scoped source read before running bounded, read-only Git with explicit arguments, not a shell (`file_explorer.rs:915`).
- Ask prompt and tool boundaries: the displayed user question excludes injected file context, while the model receives the composed question and context (`file_conversation.rs:411`). ## Extensibility

### Host hooks (`settings.hooks`)

Events: `pre_tool_call`, `post_tool_call`, `session_start`, `session_end`, `turn_start`, `turn_end`, `pre_trust_decision`. Argv only (no shell). JSON stdin; blocking JSON stdout only for `pre_tool_call` and `pre_trust_decision`. Default fail-open; `failClosed` blocks/denies on error. Matcher: exact subject equality only (`read` does not match `read_file`). `session_start` fires on the first agent turn (`begin_run`), subject `"session"`, not at process start.

### Extensions (`pi-extension.json`)

Process executables or in-process QuickJS (`.js`/`.mjs`). Capabilities: `commands`, `tools`, `event_hooks`, `message_renderers`, `provider_metadata`, `provider`, `session_actions`, `ui`, `overlays`. Project extensions load only when the project is trusted. QuickJS: dedicated thread, 64 MiB, no Node globals. QuickJS rejects `message_renderers` and `provider_metadata`. `/overlay` addresses registered overlay ids.

### Packages (`rpi install`)

Local path or git (`https`/`ssh`/`git:`). Resources: extensions, skills, prompts, themes. `npm:` is rejected here. Project packages require trust.

### Plugin marketplace (`rpi plugin`)

Standalone `pi-extension.json` packages into `<agent_dir>/extensions/<name>/`. Sources: directory, tar/tgz, HTTP(S) archive, `owner/repo` or `owner/repo@ref` GitHub, git URL (`http`/`https`/`ssh`/`file`/`git+…`), `npm:` (sha512 `dist.integrity`, HTTPS→HTTP tarball refused when registry is HTTPS). Load requires an exact `Trusted` trust-store decision. Trusted command plugins run from TUI `/name` and `/run` and from the Web Command picker / composer (RPC `run`).

### Skills, prompts, themes, MCP

- Skills: `SKILL.md`, `skill://` confined reads, selector ranking, optional classifier re-rank
- Prompt templates and JSON themes (packages or `--prompt-template` / `--theme`)
- MCP client in-session; `rpi mcp list|import` from Claude Desktop or Cursor

## Voice

Two distinct modes (`docs/src/user-guide/live.md`). The terminal does not implement WebRTC.

- **TUI STT:** `live.enabled` + `live.mode: "stt"`; `/live` hold Ctrl+Space; whole-utterance transcript lands in the composer (no interim streaming). OpenAI-compatible `{sttBaseUrl}/v1/audio/transcriptions`. Limits: 30s retained mono 16 kHz, 10s no-speech watchdog, 30s request timeout, utterances shorter than 250ms skipped. HTTPS unless `live.allowInsecure`.
- **Web STT RPC** (`stt_rpc`) for composer dictation. Hold-to-talk destination is captured at pointer-down / `startRecording` as `MainComposer` or `SideChatTab(id)` (`captureSttRecordingDestination` / `planSttTranscriptRoute` in `useSttRecorder.ts`; `startMainSttRecording` / `startSideChatSttRecording` / `onSttTranscript` in `App.tsx`), not from completion-time `activePanelRef`. Main footer while Side chat is open stays on main. There is no `insertNow`: a live dest tab always awaits `side_chat_switch(dest.tabId)` (`applySideChatSttInsert` `awaitSwitch`; `settleSideChatSttAfterSwitch` / `resolveSideChatSttInsert` in `SideChatPanel.tsx`); insert only when ACK `active === dest.tabId` and dest is still in `tabs`. Typed `discardClosed` is only panel closed, dest gone, seq superseded, or ACK `active !== dest` (`SIDE_CHAT_STT_CLOSED_TOAST`); never auto-submits on the main composer. Switch/insert errors toast `side chat switch: … (session=… tab=…)`. Catch uses `planSideChatSwitchCatchToast` + `isToastOwnedRpcError`: an already-owned toast stays silent (no second toast); otherwise display once then `toasted: true`. Unmount `!live` does not overwrite `kind: 'error'` (`finishSideChatSttInsertAfterAwait`).
- **Web realtime:** `live.mode: "realtime"`; WebRTC create-call + `oai-events` data channel; frameless v3 session config (instructions, output voice, delegation); model selection is proxy-owned (`realtime.ts` omits `model`). While the call is up, a live transcript overlay (`#realtime-transcript`) sits above the composer with connection-state (`#realtime-conn-state`) and preview text. A finalized user transcript lands in the composer as a draft and does not auto-send. Delegation flush toasts `Voice draft ready`, not that an agent started.
- Create/stop RPCs bind the session captured at call start; switching the displayed session must not move or stop another session's call
- If TUI config selects realtime, rpi directs you to the Web listener

## Platforms and release

Release matrix (`.github/workflows/release.yml`): CLI `x86_64-unknown-linux-gnu`, `aarch64-unknown-linux-gnu`, `aarch64-apple-darwin`, `x86_64-apple-darwin`, `x86_64-pc-windows-msvc`. The same tag also publishes desktop packages for Linux amd64, Linux arm64, macOS arm64, macOS x86_64, and Windows x86_64, plus one Android APK covering `armeabi-v7a`, `arm64-v8a`, `x86`, and `x86_64`. iOS is not published. Settings watch uses notify: Linux inotify, macOS FSEvents, Windows ReadDirectoryChanges. Windows has no OS confinement.

**Desktop Electron:** [`crates/pi-cli/desktop`](crates/pi-cli/desktop/README.md) hosts `/web` or `/chat`; without a runner override it starts and owns a release `rpi` on a selected plaintext loopback port and waits for `/status`. Explicit `--runner` / `RPI_DESKTOP_RUNNER` / `settings.json` `runnerUrl` selects connect-only mode; **Runner → Use local runner** drops a stored URL and starts the owned loopback process again. `--route web|chat` and the Runner menu select the route. A sandboxed, origin-scoped preload exposes only native-menu action subscription/capability registration, not Node or filesystem access. `/web` registers workspace/session creation, settings, attachment and stop actions subject to page state; `/chat` registers workspace/settings and mounted-session attachment/stop, but native New session stays disabled. Quit stops only the owned child (SIGINT, then bounded SIGKILL); external runners remain running. Self-signed listener certs use a remembered certificate exception (`trusted-pins.json`, exact origin + fingerprint), not identity pinning. `package-deb.sh` bundles the release runner and Electron into an amd64 or arm64 `.deb` (`/opt/rpi-desktop`, `/usr/bin/rpi-desktop`); `package-mac.sh` and `package-win.ps1` zip the same shell for macOS and Windows. Tag release runs those scripts. development requires a release runner and graphical Electron prerequisites. Desktop UI and packaged acceptance are **PENDING**; headless Electron launch attempts **FAILED** (exit 1). Not in the GitHub release matrix.

**Desktop local sign-in:** Managed-local mode offers **Runner → Sign in / configure provider…** and a native startup-failure action. A separate app-owned sandboxed window runs the existing provider prompts through `rpi login --json`; remote pages cannot invoke its bridge. One owned attempt is allowed, browser links require an explicit action referencing the current HTTP(S) authentication event, and credentials travel through stdin. Only credential-store completion plus child exit zero triggers one managed startup retry; stored credentials are not proof of provider access. Cancel, window closure, quit and remote transition tear down the owned attempt; cancellation does not undo already-persisted credentials. Fresh empty-config native onboarding remains **PENDING**, not established by compilation or authored tests. See the [desktop sign-in contract](crates/pi-cli/desktop/README.md#sign-in--configure-provider).
